## 1. Что это за проект

**«Бровка»** — футбольный менеджер в духе классики конца 90-х (жанр как у Football World Manager 2000, но своё название, свой дизайн и свои тексты; не копировать чужие игры, логотипы, арты).

Игроки — реальные футболисты с текущими составами. Цель — **Telegram-бот + Mini App + группа**:
- **группа Telegram = лига**: друзья (Борис, его брат и т. д.) играют одну общую карьеру, каждый за свой клуб (например, Борис за МЮ, брат за «Реал»);
- **Mini App** — у каждого свой интерфейс: состав, тактика, тренировки, переговоры, почта, карточки игроков;
- **бот** публикует в группе результаты туров, таблицу, трансферы, слухи, хет-трики, итоги сезона, а в личку шлёт уведомления («брат сделал ход», «пришло предложение за игрока»).

## 2. Платформа: Telegram Serverless (beta)

Бот, Mini App и база живут на серверах Telegram. Включается в @BotFather → бот → Serverless. Документация: https://core.telegram.org/bots/serverless . Полная справка SDK приходит вместе с CLI: после `npm i -D @tgcloud/cli` и `npx tgcloud init` смотри `docs/tgcloud-sdk.md` и `AGENTS.md` проекта — **это главный источник правды, читай его перед работой**.

### Правила, которые важно не нарушить
- Код — **JavaScript-модули в папке `tgcloud/`**, выполняются в V8-изоляте. **Нет npm-пакетов и файловой системы в рантайме.** Доступны только `sdk` (`db`, `api`, `fetch`, `InputFile`, `EndpointError`) и свои модули.
- Импорты своих модулей — **только относительные и с `.js`**: `import { x } from '../lib/engine/engine.js'`. Ничего вне `tgcloud/` импортировать нельзя.
- Раскладка: `tgcloud/schema.js` (таблицы — именованные экспорты), `tgcloud/lib/**` (общий код, подпапки можно), `tgcloud/handlers/<тип_апдейта>.js` (один уровень), `tgcloud/endpoints/<имя>.js` (один уровень).
- **Handler**: `export default async (input, ctx)` — `input` = полезная нагрузка апдейта (для `handlers/message` это `Message`), полный апдейт — `ctx.update`.
- **Endpoint**: `export default async (input, ctx)` — `input` = JSON из Mini App, `ctx.initData` — **проверенные платформой** данные Telegram (`ctx.initData.user` — кто вызвал). Отказ — `throw new EndpointError('текст', { code: 'X' })`. Mini App вызывает так: `Telegram.WebApp.Serverless.call('имя', input, (err, result) => …)` из официального `telegram-web-app.js`. Свой fetch с initData не писать.
- **База — SQLite**, построитель запросов как в Drizzle. **Каждый вызов `await`.** **Внешних ключей нет** (`.references()` падает при деплое) — целостность в коде. Колонки удаляются только через `.deprecated()`. Есть `json()` колонки.
- `npx tgcloud push` выкладывает код и статику, **но не меняет базу**. Схему применяет `npx tgcloud migrate`.
- **Mini App**: статика из папки, указанной в `tgcloud.jsonc` (`{ "static": { "source": "dist" } }`), раздаётся на `https://app<id>.tgcloud.ai/`. `push` сам не собирает фронт — сначала build.
- **Нет таймера/крона.** Код запускается только апдейтом или вызовом endpoint. Туры по расписанию — только внешним триггером (например, GitHub Actions по cron, см. npm-пакет `tgcloud-cron`, он неофициальный).
- **Нет встроенной выгрузки базы** — бэкапы делаем сами (endpoint/скрипт экспорта).
- Лимиты (время выполнения, память, размер базы, цены) **не опубликованы**. Проверять на практике, держать вызовы короткими.
- Вебхук управляется платформой по списку handlers. Не вызывать `setWebhook` руками.

### Деплой
- Локально: `npx tgcloud login` (ключ CLI из BotFather → Serverless → CLI Access), потом `npm run deploy` (build + push), при изменении схемы — `npx tgcloud migrate`.
- CI: CLI читает ключ из переменной **`TGCLOUD_TOKEN`**. План — GitHub Actions: на push в основную ветку `build` → `npx tgcloud push`. Ключ хранится в GitHub Secrets.

### Безопасность
- **Никогда не просить у Бориса токены и ключи в чат и не печатать их.** Ключ CLI — в `.tgcloud/credentials` (CLI сам кладёт, папка в `.gitignore`) или в GitHub Secrets.
- `.tgcloud/` не читать и не коммитить.
- Осторожно: у Бориса Serverless включён и на старом боте «Справочник по Г…». Игру делаем на **отдельном новом боте**, старого не трогаем.

## 3. Целевая архитектура

```
brovka/
├── CLAUDE.md
├── package.json            # devDeps: @tgcloud/cli; scripts: build, deploy, test
├── tgcloud.jsonc           # { "static": { "source": "dist" } }
├── engine/                 # ЕДИНЫЙ источник движка (ES-модули): engine.js, people.js, market.js, data/
├── web/                    # исходники Mini App (перенесённый ui.js + style.css + crest.js)
├── scripts/build.mjs       # копирует engine/ → tgcloud/lib/engine/ и собирает web/ → dist/
├── tgcloud/
│   ├── schema.js
│   ├── lib/engine/…        # копия engine/ (генерируется build-скриптом, руками не править)
│   ├── lib/game.js         # загрузка/сохранение карьеры, применение действий игрока
│   ├── handlers/message.js # команды /start, /newleague, /join, /table …
│   ├── handlers/callback_query.js
│   └── endpoints/*.js      # API для Mini App
├── tests/                  # прогоны движка в Node
└── .github/workflows/deploy.yml
```

### Принципы
- **Сервер — источник истины.** Туры, переговоры, трансферы считаются в endpoints/handlers. Mini App только показывает состояние и отправляет действия. Иначе в совместной игре можно жульничать.
- **Движок переносимый.** Перевести IIFE-модули в ES-модули (`export`), зависимость между ними — обычными импортами (у people/market сейчас циклические обращения через глобалы — развязать: например, `engine.js` экспортирует утилиты и ядро, `people.js`/`market.js` импортируют их, а ядро вызывает people/market через передаваемый объект-реестр или через отдельный модуль `game.js`). Движок не должен зависеть от `sdk` — чтобы при необходимости уехать на свой VPS (Node + Postgres) без переписывания.
- **`Math.random` → сид.** Для воспроизводимости и защиты от «переигровок» добавить детерминированный ГСЧ (например, mulberry32) с сидом, хранимым в состоянии карьеры.
- **Хранение.** Начать просто: таблица `careers` с колонкой `state json` (сейчас сохранение ~400 КБ) + номер версии для оптимистичной блокировки (чтобы два игрока не затёрли изменения друг друга). Если упрёмся в лимиты — разнести игроков/клубов по таблицам.
- **Не гонять всё состояние в Mini App.** Endpoints отдают нужные срезы (мой клуб, таблица, карточка игрока, почта игрока).
- **Матч.** Сервер симулирует матч целиком и возвращает список событий; Mini App проигрывает их поминутно как трансляцию. Замены по ходу «живого» матча в совместной игре невозможны — вместо них предматчевые установки (схема, настрой, план замен «на 60-й минуте, если проигрываем…»). Обсудить с Борисом, если захочет иначе.

### Telegram Mini App — что подключить
- `<script src="https://telegram.org/js/telegram-web-app.js"></script>`, `Telegram.WebApp.ready()`, `expand()`.
- Цвета из `Telegram.WebApp.themeParams` → наши CSS-переменные; реагировать на `themeChanged`.
- `BackButton` для карточек игроков/клубов, `MainButton` для «Играть тур» / «Готов к туру», `HapticFeedback` на голы и сделки.
- `start_param` (из ссылки `t.me/<бот>/<app>?startapp=<id_лиги>`) — открыть нужную лигу. Кнопки `web_app` в группах не работают — в группе давать ссылку `t.me/<бот>/<app>?startapp=…` (для этого в BotFather настроить Mini App / main app — проверить актуальные правила в документации).
- Не ставить `X-Frame-Options` / строгий `frame-ancestors`: Telegram Web открывает Mini App во фрейме.

## 4. План по этапам

Каждый этап заканчивается рабочим деплоем и коротким отчётом Борису: что сделано, что проверено, что нет.

**Этап A — фундамент на Serverless (одиночная игра)**
1. `npm create @tgcloud/bot` / `npx tgcloud init`, прочитать сгенерированные `AGENTS.md` и `docs/tgcloud-sdk.md`.
2. Перенести движок в `engine/` как ES-модули + сидированный ГСЧ. Тест в Node: прогон 3 сезонов, баланс не изменился (см. §7).
3. `schema.js`: `users` (tg_id, имя), `careers` (id, owner, chat_id группы, state json, version, created/updated), `memberships` (career_id, tg_id, club_id, ready).
4. Endpoints: `bootstrap` (создать/загрузить карьеру пользователя), `getView` (срезы состояния), `setLineup`, `setTactics`, `setTraining`, `negotiate` (действия переговоров), `respondMail`, `playRound`.
5. Mini App: перенести `ui.js`/`style.css`/`crest.js`, заменить localStorage на endpoints, подключить Telegram WebApp (тема, BackButton, MainButton).
6. Бот: `/start` — приветствие и кнопка открыть игру.
7. GitHub Actions: build + `tgcloud push` по `TGCLOUD_TOKEN`.
8. Выяснить реальные лимиты: время endpoint с прогоном тура, размер json-колонки, ответа.

**Этап B — лиги в группах**
- `/newleague` в группе → карьера, привязанная к `chat_id`; кнопка «Вступить» → выбор свободного клуба в Mini App.
- Ход по готовности: каждый жмёт «Готов»; когда готовы все — тур считается, бот публикует результаты, таблицу, лучшие события. Опционально дедлайн хода (через внешний cron).
- Уведомления в личку: предложения за игроков, агенты, «все готовы, тур сыгран».
- Трансферы между людьми: предложение → встречное → принять, с публикацией в группе.
- Новости-«журналист» в группе: результаты, хет-трики, слухи, трансферы, итоги сезона.

**Этап C — данные мира**
- Сборщик составов с Википедии (страницы клубов, разделы «Current squad»/«Состав»): позиция, возраст, гражданство. Запускать **вне** Serverless (VPS Бориса или GitHub Actions), на выходе — файлы данных в `engine/data/`.
- Рейтинги считать формулой (уровень лиги, возраст, позиция, игровое время, стоимость, где есть) — единообразно для всех лиг.
- Порядок: топ-5 Европы + РПЛ → вторые дивизионы → остальная Европа → Латинская Америка → Азия.
- Матчи чужих лиг — облегчённая симуляция (без поминутных событий), чтобы тур мира укладывался в лимиты.

**Этап D — турниры и сборные**
- Национальные кубки, вылет/повышение, Лига чемпионов / Лига Европы / Лига конференций, Либертадорес, азиатская ЛЧ.
- Сборные по гражданству, ЧМ/ЧЕ, приглашение тренировать сборную.

## 7. Проверка движка (обязательно после правок движка)

Прогон в Node без интерфейса, 3 сезона за клуб пользователя с автосоставом. Ожидаемые ориентиры:
- голов за матч ≈ 2,4–2,8; победы хозяев ≈ 40–46%; ничьи ≈ 22–28%;
- топ-клубы (Ливерпуль, Арсенал, Ман Сити, Челси) обычно в первой четвёрке;
- 18-летний талант прибавляет ~3–4 пункта за сезон; ветераны 32+ теряют 1–2;
- среднее настроение ≈ 60–66, «хотят уйти» — единицы;
- без ротации состава команда заметно проседает (так задумано — усталость).

Пример теста из прототипа: загрузить data + engine + people + market, `newGame(FM_DATA,'epl','MUN','Тест')`, в цикле `createMatch → simulateMatch → finishRound`, в конце сезона `endSeason` + `startNewSeason`, печатать таблицу, бомбардиров, отчёт сезона, статистику новостей и почты.
